# 未来规划

这里记录以后可能做的方向，目前还没有决定执行。

## 批量准备

先把一批岗位的简历都准备好，我集中确认一次，agent 再逐个投递。现在是一个岗位走完才开始下一个，定制一份简历约 6 分钟，75 个岗位光定制就要 7 小时以上，而且我每个都要守着。

设想的流程：

1. 从岗位库选出这一批岗位。
2. 同时定制多份简历，不打开表格，也不提交。
3. 全部做好后，我在一个列表里一次确认。
4. agent 逐个填表提交，只在遇到新问题或 CAPTCHA 时叫我。

执行前要决定的问题：

- **同时运行几个：** 定制工具能否安全地并行，同时开几个不会撞到额度限制。
- **失败怎么处理：** 一个岗位失败时，要跳过并继续，最后统一报告，不能卡住整批。
- **验证码：** 邮件验证码模块只读最新一封邮件，所以提交这一步仍然要一个一个来。
- **确认的入口：** 终端和 Discord 都要能完成这次确认。

## Chrome 插件

做一个装在我日常 Chrome 里的插件，在招聘页面上显示一个按钮，点一下就自动填表。这是我主动触发的手动模式，每次由我决定投哪个岗位，和现在由 agent 打开独立 Chrome 窗口的自动模式互补。

好处：

- **直接用我的浏览器：** 可以用已有的登录状态，也能和 Simplify 等其他插件共存。
- **CAPTCHA 更顺手：** 我本来就在页面上，可以直接处理。

执行前要决定的问题：

- **复用现有逻辑：** 规则引擎和字段识别要尽量和 agent 共用，不写两套。
- **模型和数据放哪里：** API Key、profile 和简历都不应该放进插件。可以让插件连接本机运行的 agent。
- **提交权限：** 手动模式下默认只填表，由我亲手点提交。
- **页面权限：** 只在我点按钮时读取当前页面，不申请所有网站的长期权限。

## 手机远程控制

Discord 机器人已经完成，见 README 的“用 Discord 控制 Agent”。我可以在手机上发 `/apply` 开始一次投递，并回答 agent 的问题。机器人已经用虚构资料和本地表格实测过，还没有在真实招聘网站上跑过。

还没有做的部分：

- **每日定时：** 每天在电脑前自动执行一轮，处理岗位库里合适的岗位。
- **Telegram：** 目前只支持 Discord。
- **手机上处理 CAPTCHA：** 现在 agent 只通知我回到电脑前处理。

限制：agent 运行在个人电脑上，所以电脑要保持开机和联网。
